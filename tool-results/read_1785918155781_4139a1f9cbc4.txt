     5→# 1. Краткая оценка
     6→
     7→## Исходная версия
     8→
     9→Исходная версия была функционально рабочей, визуально качественной, но архитектурно слабой.
    10→
    11→Основная проблема — один гигантский модуль `src/lib/card-constructor.ts` и одна огромная функция `initCardConstructor`.
    12→
    13→Характеристики старой версии:
    14→
    15→- примерно 2.7 тыс. строк в одном файле;
    16→- God Function около 2473–2731 строк;
    17→- 66 функций внутри одного замыкания;
    18→- 33 переменные состояния в одном scope;
    19→- 68 `addEventListener`;
    20→- 51 `querySelector`;
    21→- 11 localStorage-ключей;
    22→- 90 тем в CSS;
    23→- 71 зависимость в `package.json`, из которых реально использовалось только около 6;
    24→- `reactStrictMode: false`;
    25→- `ignoreBuildErrors: true`;
    26→- 128 non-null assertions;
    27→- отсутствие модульности;
    28→- отсутствие изолированных unit-тестов;
    29→- единственный smoke-test через Agent Browser.
    30→
    31→При этом сильные стороны старой версии были важными:
    32→
    33→- XSS-защита через `escapeHtml`;
    34→- рабочее сохранение в localStorage;
    35→- undo/redo;
    36→- экспорт PNG;
    37→- 109 passing smoke-проверок;
    38→- хороший UX и премиальный визуальный стиль;
    39→- оптимизированные точечные обновления preview через `updatePreviewField`.
    40→
    41→Но масштабирование было плохим: добавление любой функции требовало понимания всего монолита.
    42→
    43→Итоговая оценка старой версии: примерно **5.5/10**.
    44→
    45→Это был хороший MVP/прототип, но плохая основа для долгосрочной разработки.
    46→

    48→
    49→## Текущая версия
    50→
    51→Текущая версия уже сильно лучше.
    52→
    53→Выполнен крупный рефакторинг:
    54→
    55→- создан `src/orchestrator/CardCraftApp.ts`;
    56→- логика разнесена по модулям;
    57→- выделены StateManager, HistoryManager, StorageManager, PreviewRenderer, EditorRenderer, WordEditorManager, UI Kit;
    58→- добавлен Error Boundary;
    59→- удалено 17 неиспользуемых production-зависимостей;
    60→- `page.tsx` переключён на новый оркестратор через `USE_NEW_ORCHESTRATOR = true`;
    61→- старый `card-constructor.ts` оставлен только как fallback;
    62→- smoke-тесты проходят на **108/109**.
    63→
    64→Текущая модульная статистика:
    65→
    66→| Слой                   | Примерный размер |
    67→| ---------------------- | ---------------: |

    80→Раньше нужно было понимать одну функцию на 2.7 тыс. строк. Теперь можно править отдельный модуль со средней длиной около 200 строк.

    82→Итоговая оценка текущей версии: примерно **7.0/10**.

    87→- legacy-код ещё не удалён;

   286→# 5. Текущие главные риски
   287→
   288→## P0: падающий smoke-тест
   289→
   290→Один тест падает:
   291→
   292→> «Dblclick в поле редактора НЕ открывает попап».
   293→
   294→Это критично, потому что:
   295→
   296→- нарушено ожидаемое поведение;
   297→- новый оркестратор может неправильно обрабатывать dblclick;
   298→- возможен конфликт event delegation;
   299→- возможен лишний вызов word popup.
   300→
   301→Вероятная причина:
   302→
   303→- в новом orchestrator обработчик dblclick слушает слишком широкую область;
   304→- не проверяется, что событие произошло внутри `textarea`/`input` редактора;
   305→- отсутствует `stopPropagation` или guard;
   306→- старый код гасил такое событие, а новый — нет.
   307→
   308→Это нужно исправить первым.
   309→
   310→---
   311→
   312→## P1: legacy fallback всё ещё существует
   313→
   314→Старый `src/lib/card-constructor.ts` пока оставлен как fallback.
   315→
   316→Это правильно для миграции, но плохо для долгосрочной поддержки:
   317→
   318→- два параллельных пути;
   319→- риск, что кто-то случайно включит старый код;
   320→- дублирование логики;
   321→- сложнее рефакторить;
   322→- тесты могут проверять неактуальный путь.
   323→
   324→Нужно удалить legacy после подтверждения стабильности.
   325→
   326→---
   327→
   328→## P1: React StrictMode отключён
   329→
   330→`reactStrictMode: false` скрывает проблемы double-mount.
   331→
   332→Для нового оркестратора это особенно важно, потому что:
   333→
   334→- оркестратор императивно управляет DOM;
   335→- при double-mount могут создаваться дубли listeners;
   336→- могут утекать timers;
   337→- могут оставаться подписки;
   338→- могут дублироваться resize/drag/popup handlers.
   339→
   340→StrictMode нужно включать только после проверки cleanup.
   341→
   342→---
   343→
   344→## P1: нет unit-тестов
   345→
   346→Smoke-тест — это хорошо, но недостаточно.
   347→
   348→Нужны unit-тесты для:
   349→
   350→- StateManager;
   351→- HistoryManager;
   352→- StorageManager;
   353→- PreviewRenderer;
   354→- EditorRenderer;
   355→- WordEditorManager;
   356→- миграции карточек;
   357→- undo/redo;
   358→- localStorage recovery;
   359→- export-mode;
   360→- валидации данных.
   361→
   362→Без unit-тестов рефакторинг снова может деградировать.
   363→
   364→---
   365→
   366→## P2: bundle и зависимости
   367→
   368→Не сделано:
   369→
   370→- анализ размера bundle;
   371→- tree-shaking;
   372→- code-splitting;
   373→- dynamic import для тяжёлых частей, например `html-to-image`;
   374→- полная очистка неиспользуемых зависимостей.

   376→Это влияет на:
   377→
   378→- скорость загрузки;

   427→   - dblclick в input редактора;
   428→   - dblclick в preview-области;
   429→   - dblclick на карточке;
   430→   - dblclick на кнопках;

   531→## A3. Проверить race conditions между save/history
   532→
   533→В исходном аудите был риск:
   534→
   535→> `scheduleSave` и `scheduleHistoryPush` могут выполниться после undo/restore и сохранить уже отменённое состояние.
   536→
   537→Что сделать:
   538→
   539→1. Найти debounce-логику:
   540→   - `scheduleSave`;
   541→   - `scheduleHistoryPush`.
   542→
   543→2. При undo/redo/restore явно отменять pending timers.
   544→
   545→Например:
   546→
   547→```ts
   548→saveTimer?.clear();
   549→historyTimer?.clear();
   550→```
   551→
   552→или использовать `AbortController` / token-based cancellation.
   553→
   554→3. Проверить сценарий:
   555→   - пользователь вводит текст;
   556→   - сразу жмёт Ctrl+Z;
   557→   - debounce не должен сохранить отменённое состояние.
   558→
   559→Критерий готовности:
   560→
   561→- undo/redo не конфликтует с автосохранением;
   562→- localStorage содержит актуальное состояние;
