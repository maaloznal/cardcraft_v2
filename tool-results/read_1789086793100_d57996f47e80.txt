    11→## Кратко
    12→
    13→Проект прошёл путь от одного гигантского файла с God Function до модульной структуры из примерно 20 модулей. Это реальный архитектурный прогресс.

    18→- отсутствует валидация данных из localStorage;
    19→- отсутствует CSP;
    20→- `ignoreBuildErrors: true` скрывает ошибки TypeScript;
    21→- ESLint фактически ослаблен;
    22→- StateManager декларирует централизованное состояние, но часть изменений делается прямыми мутациями в обход dispatch;
    23→- undo/redo работает не для всех изменений;

    25→- оркестратор `CardCraftApp.ts` снова содержит признаки God Module;
    26→- нет unit-тестов;
    27→- production readiness ниже, чем казалось в предыдущем отчёте.
    28→
    29→Итог:
    30→
    31→> Текущая версия лучше начальной по структуре и потенциалу, но хуже по безопасности, целостности состояния и производственной готовности.

   311→## P0-1. Исправить XSS в PreviewRenderer
   312→
   313→Нужно защитить все места, где в HTML-атрибуты попадают данные из состояния.
   314→
   315→Файл:
   316→
   317→```text
   318→src/preview/PreviewRenderer.ts
   319→```
   320→
   321→Проблемные места:
   322→
   323→- `id="card-node-${card.id}"`
   324→- `data-card-id="card-node-${card.id}"`
   325→- `data-theme="${cardTheme}"`
   326→- `data-format="${settings.format}"`
   327→
   328→Что сделать:
   329→
   330→1. Добавить безопасное экранирование атрибутов.
   331→2. Использовать `escapeHtml` или отдельный `escapeAttr`.
   332→3. Для `card.id` лучше ввести жёсткий формат.
   333→
   334→Пример проверки id:
   335→
   336→```ts
   337→function sanitizeCardId(id: unknown): string {
   338→  if (typeof id !== "string") return crypto.randomUUID();
   339→  if (!/^[a-zA-Z0-9_-]{1,64}$/.test(id)) return crypto.randomUUID();
   340→  return id;
   341→}
   342→```
   343→
   344→Использовать только безопасный id:
   345→
   346→```ts
   347→const safeId = sanitizeCardId(card.id);
   348→```
   349→
   350→Критерий готовности:
   351→
   352→- невозможно инъектировать атрибут через `card.id`;
   353→- невозможно инъектировать `data-theme`;
   354→- невозможно инъектировать `data-format`;
   355→- есть тест на вредоносные значения.
   356→

   371→### card.id
   372→
   373→Правило:
   374→
   375→```ts
   376→/^[a-zA-Z0-9_-]{1,64}$/;

   393→
   394→То же самое:

   399→### settings.format
   400→
   401→Правило:
   402→
   403→- whitelist допустимых форматов;
   404→- fallback на default.

   406→### colors
   407→
   408→Все цвета должны проходить проверку:
   409→
   410→```ts
   411→/^#([0-9a-f]{3}|[0-9a-f]{4}|[0-9a-f]{6}|[0-9a-f]{8})$/i;
   412→```
   413→
   414→Или ограничить только hex-цветами.
   415→
   416→Если значение невалидно — удалить или заменить дефолтом.

   419→
   420→Проверять:
   421→
   422→```ts
   423→typeof value === "number";
   424→Number.isFinite(value);
   425→value >= 8;
   426→value <= 96;
   427→```
   428→
   429→Или использовать диапазон из бизнес-логики.

   431→### sectionStyles
   432→
   433→Добавить guard:
   434→
   435→```ts
   436→if (!sectionStyles || typeof sectionStyles !== "object") {
   437→  return {};
   438→}
   439→```
   440→
   441→Для каждого поля:
   442→
